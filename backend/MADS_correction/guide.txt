KARATE KATA CORRECTOR — DEVELOPER INTEGRATION GUIDE
════════════════════════════════════════════════════

WHAT THIS SYSTEM DOES
──────────────────────
A Python-based karate pose correction system that:
  1. Takes input from webcam OR uploaded video
  2. Detects the user's body joints using MediaPipe BlazePose
  3. Compares their joint angles to a professional reference (P3)
  4. Gives real-time correction feedback per joint
  5. Shows side-by-side skeleton view (user vs professional)
  6. Saves a session report as JSON + TXT

RECOMMENDED TECH STACK FOR WEBSITE
────────────────────────────────────
Since the core is Python, the best approach is:

  OPTION A — FastAPI backend (RECOMMENDED)
  ┌─────────────────────────────────────────────┐
  │  Browser (React/Vue/HTML)                   │
  │       ↕ HTTP requests                       │
  │  FastAPI server (Python)                    │
  │       ↕ calls                               │
  │  kata_trainer.py core functions             │
  │       ↕ reads                               │
  │  kata_reference\ files                      │
  └─────────────────────────────────────────────┘

  OPTION B — Flask backend (simpler)
  Same structure as FastAPI but simpler to set up.
  Good if you prefer minimal configuration.

  OPTION C — Streamlit (fastest to prototype)
  Pure Python web app — no frontend needed.
  Run: streamlit run kata_trainer.py
  Best for demo/prototype, not production.

HOW TO EXPOSE AS API ENDPOINTS
────────────────────────────────
The 3 key functions to wrap as API endpoints are
already inside kata_trainer.py:

  ENDPOINT 1 — Upload video and get full report
  POST /analyze_video
    Input:  video file upload (.mp4 .avi .mov)
    Output: JSON report with per-joint scores
    {
      "technique": "gedan_barai",
      "overall_score": 72,
      "joints": {
        "spine_lean":    {"angle": 115, "target": 101, "status": "warning"},
        "left_knee":     {"angle": 155, "target": 59,  "status": "error"},
        "right_elbow":   {"angle": 168, "target": 163, "status": "ok"}
      },
      "corrections": [
        "Bend your left knee deeper (155° vs target 59°)",
        "Straighten your spine (115° vs target 101°)"
      ]
    }

  ENDPOINT 2 — Process single frame (for live webcam)
  POST /analyze_frame
    Input:  base64 encoded image frame from browser webcam
    Output: JSON with angles + corrections for that frame
    {
      "frame_score": 68,
      "joints": { ... },
      "corrections": [ ... ],
      "current_move": "gedan_barai"
    }

  ENDPOINT 3 — Get reference skeleton frame
  GET /reference_frame?move=gedan_barai&frame=45
    Output: base64 encoded image of P3 skeleton
    for the requested move and frame number

LIVE WEBCAM IN BROWSER
────────────────────────
The browser captures webcam frames using:
  navigator.mediaDevices.getUserMedia()

Then sends each frame to POST /analyze_frame
every 100-200ms and draws the response overlay
on a <canvas> element.

VIDEO UPLOAD FLOW
──────────────────
  1. User uploads video via <input type="file">
  2. Frontend sends to POST /analyze_video
  3. Backend processes all frames with MediaPipe
  4. Returns full JSON report
  5. Frontend displays results + corrections

REFERENCE FILES (do not modify)
─────────────────────────────────
  thresholds.json     → angle tolerances per joint
                        GREEN  = within mean ± 1.0 std
                        YELLOW = within mean ± 1.5 std
                        RED    = outside mean ± 1.5 std

  P3_angles.json      → 816 frames × 9 angles
                        professional reference sequence

  P3_labels.json      → 17 move segments
                        {move_name, start_frame, end_frame}

  Kata_P3_Left.avi    → reference video for side-by-side view
                        200MB — serve as static file or
                        stream from server

QUICK START FASTAPI EXAMPLE
─────────────────────────────
  from fastapi import FastAPI, UploadFile
  import tempfile, os
  from kata_trainer import process_video_file

  app = FastAPI()

  @app.post("/analyze_video")
  async def analyze_video(file: UploadFile):
      with tempfile.NamedTemporaryFile(delete=False,
           suffix='.mp4') as tmp:
          tmp.write(await file.read())
          tmp_path = tmp.name
      result = process_video_file(tmp_path)
      os.unlink(tmp_path)
      return result

  Run with: uvicorn api:app --reload

DEPLOYMENT OPTIONS
───────────────────
  Local server:    uvicorn api:app --host 0.0.0.0 --port 8000
  Cloud (free):    Railway.app or Render.com (support Python)
  Cloud (paid):    AWS EC2, Google Cloud Run, Azure
  
  Minimum server specs:
    RAM:  4GB (MediaPipe needs ~1GB per session)
    CPU:  2 cores (no GPU needed)
    Disk: 2GB (for reference files + sessions)

KNOWN LIMITATIONS
──────────────────
  - MediaPipe works best with good lighting
  - Performer should be fully visible in frame
  - Side view gives better angle accuracy than front view
  - oi_zuki classification accuracy is 68% 
    (less training data than other techniques)
